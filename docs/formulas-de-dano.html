1. Visão geral: como o dano é montado, em camadas

Todo dano no Canary passa, em geral, por esta sequência:

1. Fórmula base (arma, magia, runa ou ataque de monstro)
     ↓
2. Modificadores do atacante (crítico, fatal hit, augments, especialização elemental,
   Wheel of Destiny, boosted creature / forge stacks)
     ↓
3. Mitigação do alvo (absorb%, defense, armor, mitigation%)
     ↓
   Dano final aplicado

A base quase sempre é calculada em Lua (arquivos em data/scripts/ e data-otservbr-global/), mas os números que a alimentam (nível, magic level, skill, attack value) e todos os modificadores das etapas 2 e 3 vêm do C++ (src/).

2. Núcleo do motor (C++) — as 3 fórmulas base

src/creatures/creatures_definitions.hpp (enum formulaType_t) · src/creatures/combat/combat.cpp

Os 3 tipos de fórmula que o C++ entende nativamente. Cada magia/runa/arma escolhe um deles.
TipoUsado porFórmula
COMBAT_FORMULA_LEVELMAGIC Magias e runas baseadas em Magic Level min = levelFormula × mina + minb
max = levelFormula × maxa + maxb

onde, quando a magia não define um callback Lua próprio (a maioria define):
levelFormula = level × 2 + (magicLevel + especializaçãoElemental) × 3
COMBAT_FORMULA_SKILL Ataques com arma (melee/distância) e magias "de combo" (skill-based) Delegado pra Weapon::calculateSkillFormula ou pro callback Lua da magia (ver seções 3 e 7)
COMBAT_FORMULA_DAMAGE Dano fixo, sem escala com nível/skill dano = random(mina, maxa)

A fórmula "level + magic level" (o coração de quase toda magia)

src/creatures/combat/combat.cpp, função Combat::getLevelFormula (linha 33)

levelFormula = player:getLevel() * 2 + (player:getMagicLevel() + especializaçãoMagicaElemental) * 3

Esse valor entra na fórmula genérica acima quando a magia não sobrescreve com sua própria fórmula em Lua. Na prática, quase toda magia de ataque sobrescreve (ver seção 6) — essa fórmula genérica é usada só quando nenhum callback Lua é registrado.

3. Dano de armas

src/items/weapons/weapons.cpp

ArmaFórmula do dano máximoDano mínimo
Corpo-a-corpo (melee) max = round(0.085 × attackFactor × attackValue × attackSkill1.1 + level/4) min = level/4 (0 se a arma não tiver ataque físico)
Distância (arco/besta + munição) max = round(0.09 × attackFactor × attackValue × attackSkill1.1 + level/4) min = level/4
Wand (varinha) Fixo: random(minChange, maxChange), valores definidos por item em items.xml — não escala com level/skill

attackValue = ataque físico do item + ataque elemental do item + bônus de weapon proficiency (sistema de progressão por uso de arma).
attackFactor vem de player:getAttackFactor() — varia com o modo de combate (ofensivo/defensivo/balanceado).
attackSkill1.1: o expoente 1.1 (aplicado em 2026-08-07, ver damage-skill-exponent.md) faz cada ponto de skill valer mais dano quanto mais alta a skill já está.
attackSkill = a skill relevante pro tipo de arma (club/sword/axe/distance/fist).

O dano elemental de uma arma melee (ex: espada de fogo) é calculado separadamente, com a mesma fórmula mas usando só o valor elemental como attackValue, e soma como dano secundário.

7. Magias de combo (estilo Monge, baseadas em skill)

Todas seguem a mesma estrutura, mudando só a constante SPELL_BASE_POWER:

dano = SPELL_BASE_POWER × (skill/100) × (attack/10) + calculateFlatDamageHealing()
min  = dano - dano/10   (-10%)
max  = dano + dano/10   (+10%)

calculateFlatDamageHealing() é uma baseline que cresce com o level, mas com retorno decrescente a cada 500+600×tier níveis (ver src/creatures/players/player.cpp:578). Atualizado em 2026-08-07: o ponto de partida da progressão mudou de 1/5 para 1/4 (segue subindo 1 no divisor a cada tier: 1/4 → 1/5 → 1/6...) — precisa recompilar o canary.exe pra valer. Algumas dessas magias passam o resultado por player:getHarmonyDamage(min, max) — um multiplicador adicional do sistema de combo do Monge (acertar o combo certo aumenta o dano).

8. Campos de dano (fire field, poison field, energy field...)

Runas/magias como Fire Field, Energy Wall e Poison Bomb não calculam dano diretamente. Elas só invocam um item de campo (ex: ITEM_FIREFIELD_PVP_FULL). O dano de quem pisa/fica no campo é uma condição periódica definida no próprio item, em data-otservbr-global/items.xml — segue o mesmo mecanismo genérico de Condition:addDamage(ticks, intervalo, dano) que vimos na runa Soulfire (seção 5).

Ou seja: pra "reformular" o dano de campos, o lugar certo não é um arquivo de magia, é a definição do item do campo em items.xml.

9. Dano de monstros

data-otservbr-global/monster/**/*.lua — tabela monster.attacks

Monstros não usam fórmula — cada ataque tem minDamage/maxDamage fixos, definidos manualmente por quem criou o monstro. Exemplo real (Dragon):

monster.attacks = {
	{ name = "melee", interval = 2000, chance = 100, minDamage = 0, maxDamage = -120 },
	{ name = "combat", interval = 2000, chance = 15, type = COMBAT_FIREDAMAGE,
	  minDamage = -60, maxDamage = -140, range = 7, radius = 4 },
	{ name = "combat", interval = 2000, chance = 10, type = COMBAT_FIREDAMAGE,
	  minDamage = -100, maxDamage = -170, length = 8, spread = 3 },
}

Dois multiplicadores globais entram por cima desses valores fixos:

  • Crítico de monstro — ver seção 4.
  • Attack Multiplier (Forge — monstro Influenced/Fiendish): multiplicador = base × (1.35 + (stacks-1) × 0.1)

10. Mitigação / Defesa (o lado que recebe o dano)

src/creatures/creature.cpp — Creature::blockHit / Creature::mitigateDamage / Creature::applyAbsorbDamageModifications

Depois que o dano é calculado (seções 2 a 9), ele ainda passa por isso no alvo, nesta ordem:

EtapaFórmula
1. Absorb % / flat (resistências de equipamento)dano -= dano × absorbPercent/100
dano = max(0, dano + absorbFlat)
(e o atacante pode ter um "increase%" que soma de volta)
2. Defesa (shield/skill de defesa, só physical)dano -= random(defesa/2, defesa)
3. Armadurase armor > 3: dano -= random(armor/2, armor - (armor%2+1))
se armor entre 1 e 3: dano -= 1
4. Mitigação % (Wheel of Destiny / stat de monstro)dano -= dano × mitigation/100

Se em qualquer etapa o dano cair a zero ou menos, ele é bloqueado (BLOCK_ARMOR / BLOCK_DEFENSE) e nada de dano é aplicado.
